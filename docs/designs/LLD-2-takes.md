# LLD-2 change 1: Take route, storage and audio extraction (approved design, verbatim)

Take, stored in session.takes[take_id]: take_id: str ('t1','t2',... in order); purpose: 'take'|'rep'; kind: 'mic'|'video'; source: 'recorded'|'uploaded'; file: str (original file saved as {take_id}{ext} in the session folder); audio: str ('{take_id}.wav', 16 kHz mono); duration_s: float; bar_from: int; bar_to: int; tempo_bpm: float; count_in_beats: int; downbeat_s: float|null (sent for recorded takes; null for uploads); calib_end_s: float (0 for now); status: 'processing'|'transcribed'|'diagnosed'|'done'|'failed'; error: str|null; form_status: 'none'|'processing'|'done'|'failed'; notes: []; calibrated: bool.

POST /sessions/{id}/takes. Request: multipart 'file' (audio/webm, audio/wav, audio/ogg, video/webm, video/mp4 or video/quicktime; at most 200 MB and 180 seconds) plus form fields kind ('mic'|'video'), source ('recorded'|'uploaded'), bar_from (int), bar_to (int), tempo_bpm (float, 30 to 240), count_in_beats (int, 0 to 8), downbeat_s (float, required when source is 'recorded'). Response 202 { take_id, status: 'processing' }. Errors: 404 session_not_found; 409 wrong_state (score not confirmed, i.e. session.score_status != 'confirmed'); 413 file_too_large; 415 unsupported_type (message lists the accepted types); 422 bad_request (bars outside the score, bar_from > bar_to, tempo out of range, missing downbeat_s). For "bars outside the score", read the bar count from data/sessions/{id}/score.json (key bars, a list) if present; if missing, skip that check (score parsing is merged separately).

GET /sessions/{id}/takes/{take}/media: the take's original file with its content type and HTTP range support (FileResponse is fine). Errors 404 session_not_found or take_not_found.

Logic: check the request, save the file, add the Take with status 'processing', reply 202, and start the pipeline in a background thread. One pipeline runs at a time per session (a per-session queue/lock). For this change the pipeline only does audio extraction: run ffmpeg as a subprocess ('ffmpeg -y -i {file} -vn -ac 1 -ar 16000 {take_id}.wav', 60-second limit). First get the duration and whether there is an audio stream: no audio stream -> status 'failed', error no_audio_track; longer than 180 s -> too_long; an ffmpeg failure or missing ffmpeg -> decode_failed (log a line naming ffmpeg). On success set duration_s and leave status 'processing' with a clear hook (a function run_take_pipeline(session_id, take_id) with a TODO step list: transcribe -> 'transcribed', diagnosis.run -> 'diagnosed', form.run for video) for the later pipeline-runner task.

Tests: valid WebM/WAV with fields returns 202 and take_id 't1', then 't2'; a .txt returns 415; a take before the score is confirmed returns 409; bar_to past the last bar, tempo 300, or a recorded take without downbeat_s returns 422; a silent/short generated wav extracts to a 16 kHz mono wav; a corrupt file gives decode_failed; a video without audio gives no_audio_track (generate test media with the ffmpeg binary, e.g. lavfi). Real check: testdata/trumpet_video1.mp4 produces a wav.

## Implementation notes (not part of the approved design)

- ffmpeg comes from `imageio-ffmpeg` (`imageio_ffmpeg.get_ffmpeg_exe()`), since ffmpeg is not on PATH. Duration and audio-stream presence are read from the stderr of `ffmpeg -i`. If the container gives no duration (browser WebM), the duration is measured from the extracted wav and the 180 s limit is checked after extraction.
- A wav upload would be saved as `t1.wav`, the same name as the extracted audio, so a wav original is saved as `{take_id}_upload.wav`. All other types follow `{take_id}{ext}`.
- Pipeline failures the design doesn't name (an unexpected crash) are stored as error `pipeline_error` and logged.
- `audio/x-wav` and `audio/wave` are accepted as aliases of `audio/wav`; a content-type parameter such as `;codecs=opus` is ignored.
- Layout: `takes/routes.py` (routes), `validation.py` (request checks), `take_store.py` (take records), `pipeline.py` (background run), `media_tools.py` (ffmpeg).
